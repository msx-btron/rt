Prove the bytes.

A plan for the rt memory kernels: one small Coq development that states what the bytes do, assembles them, and typechecks quickly. No proof file is in this tree yet. Nothing here has been checked by coqc.

00 / Orient

Three papers, one shape

Coq for the proofs we will write · HOL4 named where it was HOL4

The orienting system is Coq. The goal is a kernel a person can read, and a check that stays fast. If a change makes coqc slow, the change is too big.

Lean 4 is out of scope. CompCert, VST, Iris, and a full C parser are out of scope for the same reason: they are larger than the library they would be asked to justify.

PPDP 2013 · Coq

CoqASM

Andrew Kennedy, Nick Benton, Jonas B. Jensen, and Pierre-Évariste Dagand, “Coq: The World’s Best Macro Assembler?”, PPDP 2013. A subset of x86 is modelled in Coq. Notations accept ordinary assembly. The assembler produces hex bytes inside Coq, with a correctness theorem from those bytes to a separation-logic formula.

TPHOLs 2009 · HOL4

Verified Lisp, the shape

Magnus O. Myreen and Michael J. C. Gordon, “Verified LISP Implementations on ARM, x86 and PowerPC”, TPHOLs 2009, LNCS 5674. Machine-code interpreters for the core of Lisp 1.5, on top of a verified allocator and collector. The proofs are in HOL4, not Coq. We take the shape: a small program, proved down to the instruction, not the system.

Proc. IEEE 2005 · CoqPL 2021

SPIRAL, a subset

Markus Püschel and colleagues, “SPIRAL: Code Generation for DSP Transforms”, Proceedings of the IEEE, 2005. Algorithms are sparse factorizations in SPL, rewritten, then emitted as code. Patrick Brinich and Jeremy Johnson, CoqPL 2021, verified a subset of that pipeline in Coq. We take one rewrite: aligned head, a vector body, a tail.

CoqASM uses type classes and maps concrete bytes into the SSReflect library. This plan does not. No type classes, no MathComp, no SSReflect. The part we keep is the one that fits a small kernel: bytes computed inside Coq, a short statement that those bytes implement the spec, and notations only where they stay readable.

02 / Phases

Order of work

Memory before strings · i386 REP before AVX-512

Each phase is one claim a reader can hold in their head. A later phase does not start by widening the logic. It starts by naming the next instruction sequence.

The first machine-code target is the i386 string move and store in src/i386/rep/mem.s (rep movsb, rep stosb). That file is smaller than a NEON or AVX-512 body, and the bytes are obvious.

stdio, qsort, qsort_neo, and the allocator stay on the host oracle. They are not in the first Coq files. Lifting an existing binary with a decompiler, the way later tools do for a routine such as glibc strlen, is a check that can follow this kernel. It is not a substitute for it.
